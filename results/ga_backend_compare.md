동일 10개 질의를 `/v1/query`에 `include_citations=true`로 보낸 결과 비교.

| 항목 | 값 |
|------|-----|
| tenant | `ga` |
| top_k | 5 |
| OpenSearch 결과 | [`results/ga_opensearch_topk5.json`](ga_opensearch_topk5.json) · [md](ga_opensearch_topk5.md) |
| pgvector 결과 | [`results/ga_pgvector_topk5.json`](ga_pgvector_topk5.json) · [md](ga_pgvector_topk5.md) |
| 측정일 | 2026-08-26 |

## 한 줄 요약

**검색 결과는 거의 같고, 최종 답변 문장만 LLM 샘플링으로 갈라진다. 워밍업 이후 검색 자체는 pgvector가 더 빠르고, 전체 지연은 양쪽 모두 rerank(~410ms)가 지배한다.**

| 지표 | OpenSearch | pgvector |
|------|------------|----------|
| 성공 | 10/10 | 10/10 |
| citation 페이지 집합이 동일한 질의 | 9/10 | 9/10 |
| 점수까지 동일한 질의 | 9/10 | 9/10 |
| 답변 문자열 완전 일치 | 1/10 (Q1) | — |
| 사실관계(핵심 숫자·날짜) 불일치 | 없음 | 없음 |
| 검색 total (워밍업, 평균) | 467ms | 414ms |
| dense 평균 | 13.9ms | 3.5ms |
| sparse 평균 | 33.9ms | 1.3ms |
| rerank 평균 | 415ms | 408ms |

## 검색 품질

10개 질의 × top-5 = 50개 citation 중 **페이지+스니펫 기준 49개가 일치**한다.

유일한 차이는 Q4(등록면허세 기준일)의 4·5위:

| rank | OpenSearch | pgvector |
|------|------------|----------|
| 1–3 | p.36 / 37 / 4 (점수 동일) | 동일 |
| 4 | p.6 (0.1409) 세정팀 월별업무·정기분 등록면허세 | p.3 (0.1033) 월별 주요업무 |
| 5 | p.3 (0.1033) | p.4 (0.0989) 등록분 설명 |

둘 다 1위 청크에서 **1월 1일**을 이끌어 답변이 같다. ranking 차이는 사실 판단에 영향 없음.

핵심 결론은 10개 모두 같다. 다른 것은 문장 길이와 인용 표현이다.

## 지연

첫 질의의 임베딩 로드가 한쪽에만 잡힌다.

- pgvector Q1 `embedding_ms` = **6813ms** (콜드 스타트)
- OpenSearch Q2 `embedding_ms` = **7849ms** (이 런에서 GPU 모델 로드)

워밍업 이후:

| 단계 | OpenSearch | pgvector | 비고 |
|------|------------|----------|------|
| embedding | ~0.6ms | ~0.4ms | 캐시된 쿼리 임베딩 |
| dense | 13.9ms | 3.5ms | pgvector HNSW가 더 짧음 |
| sparse | 33.9ms | 1.3ms | OpenSearch BM25가 더 김 |
| fusion | 0.03ms | 0.03ms | |
| rerank | 415ms | 408ms | 병목, 백엔드와 무관 |
| retrieve total | 467ms | 414ms | |

엔드투엔드(LLM 포함) 10건 합계는 OS 23.3s, PG 23.1s로 비슷하다. 생성 시간이 검색 차이를 가린다.

질의별 retrieve `total_ms` (양쪽 워밍업된 Q3–Q10):

|------|------------|----------|
| Q3 | 485 | 442 |
| Q4 | 471 | 393 |
| Q5 | 485 | 447 |
| Q6 | 441 | 387 |
| Q7 | 462 | 420 |

콜드 스타트는 비교에서 제외: pgvector Q1 embedding **6813ms**, OpenSearch Q2 embedding **7849ms** (GPU에 BGE-M3 최초 로드).

## 해석

이 코퍼스(세무과 매뉴얼 PDF, tenant `ga`)에서는 **두 백엔드가 같은 청크를 거의 같은 순서로 돌려준다.** 점수까지 9/10 질의가 소수점 4자리까지 같다. 같은 임베딩 모델 + 같은 reranker를 쓰기 때문이다.

pgvector가 유리한 점: dense/sparse 검색 지연.  
OpenSearch가 유리한 점: 이 실험에서는 품질 우위를 보이지 않음(동점).

운영 선택 기준은 품질이 아니라 **인프라(이미 PG를 쓰는지, Nori/규모)** 쪽이 맞다.
